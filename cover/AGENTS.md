## Agent 使用规范

### 基本原则

- 优先选择简单、可维护的方案，避免过度设计。
- 在修改前先理解现有结构与约定，不盲目改动。
- 仅针对当前任务做最小必要修改，避免顺手重构无关内容。
- 保持与现有代码风格、命名方式、格式一致。
- 只在必要时添加注释，重点说明不直观的逻辑。
- 非必要不引入新的依赖或工具。
- 如果项目有测试或校验流程，修改后应运行相关检查。
- 遇到不明确的地方，做出合理假设并简要说明。
- 未经明确要求，不删除文件或覆盖用户已有内容。

### 联网与信息获取

- 每次用户提问时，应优先考虑调用联网工具进行检索。
- 对于涉及最新信息、事实核验、技术文档、版本差异、API 行为、价格、政策或新闻等内容，必须联网确认。
- 尽可能进行多源搜索与交叉验证，避免依赖单一来源。
- 在回答中引用外部信息时，应尽量提供来源依据或可追溯信息。

### 澄清与询问机制

- 如果用户问题存在模糊、歧义或上下文不足，必须先询问再执行。
- 对可能影响结果的关键前提（环境、版本、目标、约束等），应主动确认。
- 使用 IDE 系统内置的“询问模式”与用户交互。
- 每次提问时，应提供结构化选项以帮助用户快速选择。
- 所有询问选项中，**必须包含一个允许用户自由输入想法的选项**（如：“其他 / 自定义输入”）。
- 在未完成澄清前，不执行可能产生较大影响或不可逆的操作。
