# 全局代理行为规范

## 文本文件编辑

1. 手工创建、修改或删除文本文件时，应优先使用当前会话提供的 Codex 原生结构化补丁工具，例如 `apply_patch`。本规则适用于所有文本文件，不限于源代码。
2. 原生补丁工具可用且适合当前操作时，不得仅为操作便利，改用终端命令、PowerShell、Python 或其他脚本直接写入或重写文本文件。
3. 原生补丁工具未提供、调用失败或无法完成当前操作时，应简要说明原因，再在现有权限及其他指令允许的范围内使用适当的替代编辑方式。不得尝试调用未提供的工具。
4. 读取文件、搜索内容、执行测试及其他非编辑操作，可以正常使用终端工具。格式化、代码生成和依赖管理等操作，可以使用各自的标准工具，不要求改为手工补丁。
5. 是否使用补丁工具，应以当前实际提供的工具及其能力为依据，不应依赖对 App、CLI 或 VS Code 扩展等客户端身份的推测。
6. 使用补丁工具不代表客户端必然显示逐轮 Diff 或变更审阅卡片。不得保证尚未验证的界面行为。

## 最终回复结束语

1. 每次面向用户的最终回复，必须以以下文字作为结束语，并独立成行，使用 Markdown 加粗格式：

   **很高兴为恁提供服务**

2. 应完整保留结束语的原文，不得将“恁”替换为“您”，不得改变措辞。
3. 本要求适用于最终回复，不要求在进度说明或工具调用中重复添加。除非用户另有要求，不得将该结束语作为无关内容追加到代码、命令或交付文件中。
4. 该结束语用于辅助用户检查当前回复是否遵循本规范，不构成其他会话或客户端已加载该文件的证明。
